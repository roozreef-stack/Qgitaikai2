# キャンパス謎解きウォークラリー

学内イベント用の、位置情報つき謎解きウォークラリーWebアプリです。
参加者は自分のスマホのブラウザで、チェックポイント（CP）ごとの謎を好きな順に解きます。謎に正解するとCPの場所が地図に現れ、現地に着くと「現地の問題」が出て、それに正解するとクリアです。全CPをクリアすると最終メッセージが表示されます。終了日時になるとゲームは終了し、それまでのクリア数が結果になります。

- HTML / CSS / JavaScript だけの静的サイトです（ビルド不要・サーバー側の処理なし）
- 進捗は各端末のブラウザ（localStorage）に保存されます
- 対応ブラウザ：iPhone の Safari、Android の Chrome

## 遊び方の流れ

1. 「謎の一覧」から好きなCPを選び、謎を解いて答えを入力する（**どこにいても答えられます**）
2. 正解すると、そのCPのピンが「地図」に現れ、コンパスと残り距離が使えるようになる
3. 現地へ向かい、半径内（既定25m）に入ると「現地の問題」と入力欄が出る
4. 現地でしか分からない答えを入力するとクリア
5. 全CPをクリアするとゴール。最終メッセージが出る

CPの状態は「未解答 → 場所が判明 → クリア」の3段階です。ヒント・ギブアップの機能はありません。

## ファイル構成

```
index.html              画面の骨組み
style.css               見た目
app.js                  画面制御・状態管理・時間制限・進捗保存・デバッグモード
geo.js                  距離・方位の計算、位置情報と端末の向きの取得
data/checkpoints.json   CP・謎・答え・最終メッセージ・終了日時（運営が編集する唯一のファイル）
requirements.md         要件定義書
README.md               このファイル
```

## PCで動かす

`index.html` をダブルクリックして開く（`file://`）と、JSONを読み込めず動きません。ローカルサーバーを立てて開いてください。

```sh
# どちらか一方
python -m http.server 8000
npx serve .
```

ブラウザで `http://localhost:8000/` を開きます（localhost は HTTPS でなくても位置情報が使えます）。

### デバッグモード

URLの末尾に `?debug=1` を付けると、PCでもひととおりの流れを確認できます。

```
http://localhost:8000/?debug=1
```

| 操作 | 方法 |
|---|---|
| 現在地を指定 | 「地図」タブで地図をタップした位置が現在地になる。「選択中のCPへ移動」で、選んだCPの判定位置に移動（現地の問題の確認に使う） |
| 端末の向きを指定 | 「端末の向き」スライダー（0〜359°） |
| 全CPを場所判明にする | 「全CPを場所判明に」（地図に13個のピンが出る） |
| ゴール画面を確認 | 「全CPクリア（ゴール確認）」（最終メッセージが出る） |
| 時刻を進める | 「時刻 +1分」「+10分」「終了10秒前へ」（時間切れの確認） |
| 終了日時を上書き | `?debug=1&endAt=2026-11-30T16:00:00%2B09:00`（`+` は `%2B` と書く） |
| 最初からやり直す | 「進捗をリセット」（確認ダイアログあり） |

デバッグモードでは位置情報・センサーの許可を求めません。上書きした終了日時や時刻のずれは、デバッグモードのときだけ有効です。

## 運営が差し替える内容（`data/checkpoints.json`）

座標・謎・答え・現地の問題・最終メッセージ・終了日時はすべてダミーです。本番前にこのファイルだけを編集してください。コードの変更は不要です。

```json
{
  "gameTitle": "キャンパス謎解きウォークラリー",
  "endAt": "2026-11-30T16:00:00+09:00",
  "finalMessage": "全CPクリア後に表示する文章。\n改行できます。",
  "mapCenter": { "lat": 35.0000, "lng": 135.0000, "zoom": 17 },
  "checkpoints": [
    {
      "id": "cp1",
      "name": "CP1",
      "puzzle": "場所を当てる謎の文章",
      "answer": ["謎の答え", "別表記"],
      "lat": 35.0000,
      "lng": 135.0000,
      "arrivalRadius": 25,
      "siteQuestion": "現地で分かる問題の文章",
      "siteAnswer": ["現地の答え"]
    }
  ]
}
```

| 項目 | 内容 |
|---|---|
| `gameTitle` | スタート画面と結果画面に出るタイトル |
| `endAt` | 終了日時。ISO 8601 形式で、日本時間のオフセット `+09:00` を必ず付ける |
| `finalMessage` | 全CPクリア時にゴール画面で表示する文章。`\n` で改行できる。省略すると「ゴールおめでとうございます！」だけ表示 |
| `mapCenter` | ピンが1つもないときの地図の中心 |
| `id` | CPごとに重複しない文字列。進捗の保存に使うので、開催中は変えない |
| `name` | 一覧・ピン・パネルに出る名前（例：`CP1`）。ピンに収まるよう短くする |
| `puzzle` | 場所を当てる謎の文章。`\n` で改行できる |
| `answer` | 謎の答え。文字列、または候補の配列（例：`["図書館", "としょかん"]`） |
| `lat` / `lng` | CPの正確な座標。ピンの位置・コンパス・残り距離・到着判定のすべてに使う |
| `arrivalRadius` | 到着とみなす半径（m）。省略すると 25 |
| `siteQuestion` | 到着すると出る現地の問題の文章 |
| `siteAnswer` | 現地の問題の答え。`answer` と同じく文字列または配列 |

**答えの照合ルール**（`answer` / `siteAnswer` 共通）：全角／半角、大文字／小文字、前後の空白、ひらがな／カタカナの違いは区別しません。それ以外の表記ゆれ（「図書館」と「としょかん」など）は、候補を配列で並べてください。

- CPの数は自由です。件数に合わせて「n / 件数」の表示や全クリア判定が変わります。
- 項目が足りない・書式が違う場合は、画面にどのCPのどの項目が問題か表示されます。保存前に [JSONの検証ツール](https://jsonlint.com/) などで確認しておくと安全です。

### 問題を作るときの注意

- **謎の答えと現地の答えを別のものにしてください。** 重なると、現地へ行かなくてもクリアできてしまいます。
- **現地の答えは、現地でしか分からないものにしてください**（掲示物の数字、看板の文字など）。写真や記憶、他の参加者の話だけでは答えられないものが安全です。
- ヒント機能がないので、謎が難しすぎると場所にたどり着けない参加者が出ます。事前に何人かに解いてもらって難易度を確認してください。
- 地図のピンは正確な座標に出ます。謎に正解した人にだけ場所が見える仕組みです。

### 座標の取り方（Googleマップ）

1. PCのGoogleマップで、CPの位置を右クリックします（スマホは長押し）。
2. 先頭に出る `35.00123, 135.00456` のような数字をクリックするとコピーされます。前が緯度（`lat`）、後ろが経度（`lng`）です。

### 終了日時を変えるときの注意

進捗は終了日時ごとに別々に保存されます。**開催中に `endAt` を変えると、参加者全員の進捗がリセットされます。** 当日は変更しないでください（別の回として開催し直すときは、変えればまっさらな状態から始まります）。

## 公開手順（HTTPS必須）

位置情報と向きセンサーは HTTPS のページでしか使えません。次のどちらかで公開します。

### GitHub Pages

1. GitHub で新しいリポジトリを作り、このフォルダの中身をすべてアップロードします（`index.html` がリポジトリの一番上に来るようにする）。
2. リポジトリの Settings → Pages → Build and deployment で、Source を「Deploy from a branch」、Branch を `main` / `/ (root)` にして Save。
3. 数分後に `https://<ユーザー名>.github.io/<リポジトリ名>/` で公開されます。

JSONを直したときは、GitHub上で `data/checkpoints.json` を編集して保存すれば、数分で反映されます。

### Netlify

1. https://app.netlify.com/drop を開きます。
2. このフォルダごとドラッグ＆ドロップすると、`https://〜.netlify.app` のURLが発行されます。

更新するときは、Netlify のサイト管理画面の Deploys から、フォルダをもう一度ドラッグ＆ドロップします。

公開URLは QRコードにして掲示すると、参加者が開きやすくなります。

## 参加者への案内（そのまま配布できます）

- iPhone は **Safari**、Android は **Chrome** で開いてください。
- **端末の時刻を「自動設定」にしてください。** 残り時間は端末の時計で計算するため、時計がずれていると終了時刻もずれます。
  - iPhone：設定 → 一般 → 日付と時刻 → 自動設定 をオン
  - Android：設定 → システム → 日付と時刻 → 時刻を自動的に設定 をオン
- スタートすると「位置情報」と「動作と方向（向き）」の利用許可を求められます。どちらも許可してください。
- 謎の答えは、どこにいても入力できます。正解するとCPの場所が地図に現れます。現地に着くと、現地の問題が出ます。
- プライベートブラウズ（シークレットモード）では進捗が保存されないことがあります。通常のタブで開いてください。
- 進捗はその端末のそのブラウザに保存されます。途中で別の端末やブラウザに変えると引き継げません。
- ゲームが終わったら、結果画面のスクリーンショットを運営に見せてください。

## 当日までに運営が確認すること

アプリ側では現地テストができないため、以下は実機で確認してください。

- [ ] 公開URLが HTTPS で開ける
- [ ] `endAt` が本番の終了日時（`+09:00` 付き）になっていて、スタート画面の終了日時が正しく表示される
- [ ] 13か所すべてで、謎の答え・現地の答えが正しく通る（表記ゆれの候補が足りているか）
- [ ] 13か所すべてで、現地に立つと現地の問題が出る（GPSの誤差を確認。反応が悪い場所は `arrivalRadius` を広げる）
- [ ] 謎の答えと現地の答えが重なっていない
- [ ] 鉄筋の建物の近くで、コンパスの矢印が大きくずれないか
- [ ] iPhone / Android それぞれで、許可の確認が出て、地図・コンパス・答え入力が動く
- [ ] `finalMessage` が意図した文面で、ゴール画面に表示される（デバッグモードの「全CPクリア」で確認できる）
- [ ] 複数の端末で、同じタイミングで時間切れになる（全端末の時刻が自動設定になっているか）
- [ ] 確認に使った端末は、デバッグモードの「進捗をリセット」で最初の状態に戻しておく

## 補足

- 地図は OpenStreetMap のタイルを使っています。イベント規模（数十〜数百人）なら問題ありませんが、大量アクセスは OSM の[タイル利用ポリシー](https://operations.osmfoundation.org/policies/tiles/)に反するので注意してください。
- 答え・座標・最終メッセージは JSON に平文で入っています。ブラウザの開発者ツールで見ようと思えば見られます（MVPでは秘匿しない方針）。
- 外部への通信は、地図タイルと Leaflet（unpkg.com の CDN）だけです。
